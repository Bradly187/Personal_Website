ClinicScheduler

Full-stack scheduling system for a pain-management clinic — ASP.NET Core, Blazor, and Entity Framework Core over PostgreSQL on a clean, layered architecture. Role-based access with TOTP two-factor auth, conflict-aware booking across therapists, rooms, and patients, recurring treatment-plan scheduling, and an automated waitlist that re-fills canceled slots. Built as a Systems Analysis & Design capstone, then hardened toward production — HIPAA-style audit logging, structured logging and health checks, optimistic concurrency, and 199 unit tests plus an integration suite against real PostgreSQL — and codified for AWS with Terraform and a CI/CD pipeline.

// Features
Role-Based Access + MFA Five roles — Admin, Clinic Manager, Therapist, Staff, Patient — enforced with ASP.NET Core Identity, plus opt-in TOTP two-factor auth with QR enrollment and recovery codes.
Conflict-Aware Scheduling Prevents double-booking across therapist, room, and patient — with per-location operating hours, slot durations, and daily capacity, all configurable.
Recurring Treatment Plans One click books a plan’s full series — 2–4 sessions a week at the preferred day and time, falling back to the nearest open slot.
Automated Waitlist Canceled slots are offered to the oldest matching waitlist entry instantly; a background sweep fills the rest and notifies patients.
Request & Approval Workflow Patients request appointments; staff approve or deny; missed visits auto-reschedule to the next open slot.
Multi-Channel Reminders 24-hour appointment reminders in-app, by email, and by SMS — texts strictly gated on documented patient consent.
Audit & Access Logging Append-only audit trail attributing every change to its user, plus HIPAA-style read-access logging on patient records.
REST API & Integrations Documented OpenAPI surface with pagination and optimistic concurrency; ingests verified records from the serverless identity pipeline.
Cross-Platform Client Blazor web (Server + WebAssembly) with a .NET MAUI shell — one codebase, multiple targets.
Production Observability Serilog structured logging (JSON in production), load-balancer health checks, rate-limited login, and security headers throughout.
Infrastructure as Code The entire AWS stack — VPC, ECS Fargate, RDS PostgreSQL, ALB, ECR, Secrets Manager — defined in modular Terraform.
CI/CD Pipeline GitHub Actions builds and tests every push and PR, authenticating to AWS via OIDC — deploys are an explicit one-click action, never automatic.
// Cloud architecture

The deployment is defined entirely as code with Terraform. An Application Load Balancer fronts an ECS Fargate service running the containerized app; a managed RDS PostgreSQL instance sits in private subnets, reachable only from the app tier. Database credentials and the seed admin secret are injected at runtime from AWS Secrets Manager, and a GitHub Actions pipeline builds the image to ECR and rolls the service using short-lived, OIDC-federated IAM roles — no long-lived cloud keys.

Internet → ALB → ECS Fargate (app :8080) → RDS PostgreSQL (private)
Secrets Manager → app  ·  ECR ← GitHub Actions (OIDC) → ECS deploy
